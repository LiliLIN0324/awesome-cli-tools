# 收录标准 / Inclusion Criteria

> 本文件是**准入规则**，不是推荐排序。满足标准只代表「可以被收录」，
> 不代表「一定被收录」；但违反标准一定会被拒绝。

## 硬性门槛（Hard requirements）

一个工具要被收录，必须**同时**满足：

| # | 要求 | 判定方式 | 不满足时 |
| --- | --- | --- | --- |
| H1 | 存在官方仓库或官网可供追溯 | 链接可打开，且非第三方镜像 | 拒绝 |
| H2 | 许可证明确 | 仓库有 `LICENSE` 或在 README 声明；闭源工具须写明为专有 | 拒绝 |
| H3 | 近 18 个月内有发布或提交 | 查 release / commit 时间 | 拒绝（可标注为「归档」，见下） |
| H4 | 能在无 GUI 环境下工作 | 纯 shell 可跑；即使有 TUI 也能被脚本调用 | 拒绝 |
| H5 | 有非交互式用法 | 支持参数/管道/`--json` 等，而不是只能聊天式交互 | 拒绝 |
| H6 | 安装可复现 | 官方渠道（包管理器、release 二进制、cargo/npm/go/pip、brew） | 拒绝 |

## 加权偏好（Preferred, not required）

- **退出码语义正确**：0 成功 / 非 0 失败，便于 `set -e` 与 CI。
- **提供机器可读输出**：`--json`、`--porcelain`、NDJSON。
- **尊重 `NO_COLOR` 与 `--color=never`**：不污染日志与管道。
- **单一静态二进制或极易安装**：降低试用成本。
- **配置文件在 `~/.config` 或遵循 XDG**：不污染家目录。
- **跨平台**（至少 macOS + Linux + Windows 三选二）。

## 明确排除（Rejected outright）

- ❌ 完全只在 GUI 里可用的「命令行安装器」。
- ❌ 需要付费账号才能**启动**（只有高级功能付费是允许的）。
- ❌ 无来源二进制分发、混淆代码、捆绑安装器。
- ❌ 已归档（archived）且无活跃 fork —— 若该工具仍不可替代，可在表中
  保留并显式标注 `⚠️ 已归档`，但必须给出替代方案。
- ❌ 采集遥测且**无法关闭**，或未在文档中披露。
- ❌ 与已有条目重复且没有任何差异化说明。
- ❌ 纯 API 文档搬运、纯广告页、affiliate 链接。

## 什么算「优质」

用于排序同一小节内的条目（从高到低）：

1. **解决一个具体问题**，而不是「什么都能做」。
2. **默认行为正确**，不需要大量 flag 才可用。
3. **错误信息可读**，能告诉你哪里错了以及怎么修。
4. **文档与 `--help` 一致**，不靠博客文章猜用法。
5. **专注**：一个工具做一件事，组合能力强（Unix 哲学）。
6. **可预测**：不偷偷联网、不偷偷改配置。

## 标注约定

| 标注 | 含义 |
| --- | --- |
| `⚠️ 已归档` | 无维护，但生态仍有引用；必须附替代方案 |
| `⚠️ 需登录` | 首次使用需要账号或 API Key |
| `⚠️ 遥测` | 默认上报数据（即使可关闭） |
| `⚠️ 专有` | 非开源，许可证为商业/专有条款 |
| `⚠️ 平台限定` | 仅单一操作系统可用 |

## 复核周期

每条收录建议每 **12 个月**复核一次。复核内容包括：工具是否还在维护、
许可证是否变更（例如从开源转为 BUSL）、是否有更好的替代品。
深度页的 `最后复核` 字段用于记录这件事。
